[#day2-migration-mgmt-prereq]
=== 先决条件

ifeval::["{flavor}" == "telco"]
==== 升级裸机操作员 CRD

[NOTE]
====
仅适用于需要 <<components-metal3>> chart 升级的 CAPI/Metal3 管理集群。
====

`Metal^3^` Helm chart 通过利用 Helm 的 link:https://helm.sh/docs/chart_best_practices/custom_resource_definitions/#method-1-let-helm-do-it-for-you[CRD] 目录包含 link:https://book.metal3.io/bmo/introduction.html[Bare Metal Operator (BMO)] CRD。

然而，这种方法有一定的局限性，特别是无法使用 Helm 升级此目录中的 CRD。有关详细信息，请参见 link:https://helm.sh/docs/chart_best_practices/custom_resource_definitions/#some-caveats-and-explanations[Helm 文档]。

因此，在将 Metal^3^ 升级到 `{product} {static-edge-version}` 兼容版本之前，用户必须手动升级底层的 BMO CRD。

在安装了 `Helm` 且 `kubectl` 配置为指向您的 `{cluster-type}` 集群的机器上：

. 手动应用 BMO CRD：
+
[,bash,subs="attributes"]
----
helm show crds oci://registry.suse.com/edge/charts/metal3 --version {version-metal3-chart} | kubectl apply -f -
----
endif::[]

[#day2-migration-mgmt-upgrade-controller]
=== 升级控制器

[IMPORTANT]
====
`Upgrade Controller` 目前仅支持 `{product}` 版本迁移，仅适用于 *非隔离的管理* 集群。
====

本节涵盖以下主题：

<<day2-migration-mgmt-upgrade-controller-prereq>> - `Upgrade Controller` 的特定先决条件。

<<day2-migration-mgmt-upgrade-controller-migration>> - 使用 `Upgrade Controller` 将 `{cluster-type}` 集群迁移到新 `{product}` 版本的步骤。

[#day2-migration-mgmt-upgrade-controller-prereq]
==== 先决条件

===== {product} {version} 升级控制器

在使用 `Upgrade Controller` 之前，您必须首先确保其运行的版本能够迁移到所需的 `{product}` 版本。

要执行这一操作：

. 如果您已经从之前的 `Upgrade Controller` 版本部署了 `{product}`，请升级其 chart：
+
[,bash,subs="attributes"]
----
helm upgrade upgrade-controller -n upgrade-controller-system oci://registry.suse.com/edge/charts/upgrade-controller --version {version-upgrade-controller-chart}
----

. 如果您 *没有* 部署 `Upgrade Controller`，请遵循 <<components-upgrade-controller-installation>>。

[#day2-migration-mgmt-upgrade-controller-migration]
==== 迁移步骤

使用 `{cluster-type}` 执行 `Upgrade Controller` 集群迁移与执行升级基本相似。

唯一的区别是您的 `UpgradePlan` *必须* 指定 `{static-edge-version}` 发布版本：

[,yaml,subs="attributes"]
----
apiVersion: lifecycle.suse.com/v1alpha1
kind: UpgradePlan
metadata:
  name: upgrade-plan-mgmt
  # Change to the namespace of your Upgrade Controller
  namespace: CHANGE_ME
spec:
  releaseVersion: {static-edge-version}
----

有关如何使用上述 `UpgradePlan` 进行迁移的信息，请参阅 <<{cluster-type}-day2-upgrade-controller, Upgrade Controller 升级流程>>。

[#day2-migration-mgmt-fleet]
=== Fleet

[NOTE]
====
尽可能使用 <<day2-migration-mgmt-upgrade-controller>> 进行迁移。

仅在 `Upgrade Controller` 未涵盖的用例中参考本节。
====

使用 `{cluster-type}` 执行 `Fleet` 集群迁移与执行升级基本相似。

*关键*区别在于：

. 必须使用 `suse-edge/fleet-examples` 储存库的 link:https://github.com/suse-edge/fleet-examples/releases/tag/{static-fleet-examples-tag}[{static-fleet-examples-tag}] 版本中的 *Fleet*。

. 计划升级的 Chart *必须*升级到与 `{product} {static-edge-version}` 版本兼容的版本。有关 `{product} {static-edge-version}` 组件的列表，请参阅 <<release-notes-3-7-0>>。

[IMPORTANT]
====
为确保 `{product} {static-edge-version}` 迁移成功，用户务必遵守上述要点。
====

ifeval::["{flavor}" == "edge"]
考虑到上述几点，用户可以遵循 `{cluster-type}` 集群 <<{cluster-type}-day2-fleet, Fleet>> 文档，获取执行迁移所需步骤的综合指南。
endif::[]
