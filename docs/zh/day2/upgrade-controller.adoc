[IMPORTANT]
====
`Upgrade Controller` 目前仅支持 *非隔离的管理* 集群的 `Day 2` 操作。
====

本节介绍了如何执行与将 `management` 集群从一个 `{product}` 平台版本升级到另一个版本相关的各种 `Day 2` 操作。

`Day 2` 操作由 <<components-upgrade-controller, 升级控制器>> 自动执行，包括：

* <<components-slmicro, SUSE Linux Micro>> 操作系统升级
ifeval::["{flavor}" == "edge"]
* <<components-rke2>> 或 <<components-k3s>> Kubernetes 升级
endif::[]
ifeval::["{flavor}" == "telco"]
* <<components-rke2>> Kubernetes 升级
endif::[]
* SUSE 附加组件（SUSE Rancher Prime、SUSE Security 等）升级

=== 先决条件

在升级您的 `management` 集群之前，必须满足以下先决条件：

. `SCC registered nodes` - 确保您的集群节点操作系统已使用支持您打算升级到的 `{product}` <<release-notes,版本>> 中指定的操作系统版本的订阅密钥进行注册。

. `Upgrade Controller` - 确保 `Upgrade Controller` 已部署在您的 `management` 集群上。有关安装步骤，请参阅 <<components-upgrade-controller-installation>>。

=== 升级

. 确定您希望将 `management` 集群升级到的 `{product}` <<release-notes,版本>>。

. 在 `management` 集群中，部署一个指定所需 `UpgradePlan` 的 `release version`。`UpgradePlan` 必须部署在 `Upgrade Controller` 的名称空间中。
+
[,bash]
----
kubectl apply -n <upgrade_controller_namespace> -f - <<EOF
apiVersion: lifecycle.suse.com/v1alpha1
kind: UpgradePlan
metadata:
  name: upgrade-plan-mgmt
  namespace: upgrade-controller-system  # replaces it if the upgrade controller has been deployed in a different namespace
spec:
  # Version retrieved from release notes
  releaseVersion: 3.X.Y
EOF
----
+
[NOTE]
====
在某些用例中，您可能希望对 `UpgradePlan` 进行额外配置。有关所有可能的配置，请参考 <<components-upgrade-controller-extensions-upgrade-plan>>。
====

. 将 `UpgradePlan` 部署到 `Upgrade Controller's` 名称空间将开始 `upgrade process`。
+
[NOTE]
====
有关实际 `upgrade process` 的详细信息，请参考 <<components-upgrade-controller-how>>。

有关如何跟踪 `upgrade process` 的信息，请参考 <<components-upgrade-controller-how-track>>。
====

=== 升级后步骤
`{product}`从最新的 `{previous-edge-version}` z-stream 升级到 `{static-edge-version}` 需要在 `Upgrade Controller` 完成升级过程后执行最后的几个手动步骤，这与 `rke2-traefik` 版本中包含的 Helm chart 中的一些 Helm 参数更改有关。`{product}``{static-edge-version}`

* 在 `helmchartconfigs.helm.cattle.io/rke2-traefik` 名称空间中应用 `kube-system` API 对象中的以下更改（或者，如果该 API 对象不存在，则在 `helmcharts.helm.cattle.io/rke2-traefik` API 对象中应用它们）：
[NOTE]
====
使用 `HelmChartConfig`（或 `HelmChart`）清单按如下所示应用这些更改，以确保 `Upgrade Controller` 在未来的管理集群升级中保留它们。
====

[,shell]
----
# You can use `kubectl edit', `kubectl patch` or `kubectl apply` commands to apply the changes indicated below
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: rke2-traefik
  namespace: kube-system
spec:
  failurePolicy: reinstall
  valuesContent: |-
    ingressClass:
      isDefaultClass: true
    ports:
      web:
        hostPort: null
        exposedPort: 80
      websecure:
        hostPort: null
        exposedPort: 443
    service:
      enabled: true
      # type: LoadBalancer              # CHANGE_1: This Helm parameter has been REMOVED
      # ipFamilyPolicy: PreferDualStack # CHANGE_2: This Helm parameter has been REMOVED
      spec:
        type: LoadBalancer              # CHANGE_3: NEW Helm parameter replacing the old/removed one (above)
        ipFamilyPolicy: PreferDualStack # CHANGE_4: NEW Helm parameter replacing the old/removed one (above)
        externalTrafficPolicy: Local
        allocateLoadBalancerNodePorts: false
    providers:
      kubernetesIngressNGINX:           # CHANGE_5: NEW Helm parameter replacing the old/removed "KubernetesIngressNginx"
        enabled: true
        ingressClass: "rke2-ingress-nginx-migration"
        controllerClass: "rke2.​cattle.​io/ingress-nginx-migration"
EOF
----

或者，如果 `helmchartconfigs.helm.cattle.io/rke2-traefik` 名称空间中的 `kube-system` API 对象不存在：

[,shell]
----
# You can use `kubectl edit', `kubectl patch` or `kubectl apply` commands to apply the changes indicated below
apiVersion: helm.cattle.io/v1
kind: HelmChart
metadata:
  name: rke2-traefik
  namespace: kube-system
spec:
  chart: rke2-traefik
  version: {rke2-traefik Helm chart version}
  repo: https://rke2-charts.rancher.io
  bootstrap: false
  failurePolicy: reinstall
  backOffLimit: 20
  targetNamespace: kube-system
  set:
    global.cattle.systemDefaultRegistry: registry.rancher.com
    global.rke2DataDir: /var/lib/rancher/rke2
    global.systemDefaultRegistry: registry.rancher.com
  valuesContent: |-
    ingressClass:
      isDefaultClass: true
    ports:
      web:
        hostPort: null
        exposedPort: 80
      websecure:
        hostPort: null
        exposedPort: 443
    service:
      enabled: true
      # type: LoadBalancer              # CHANGE_1: This Helm parameter has been REMOVED
      # ipFamilyPolicy: PreferDualStack # CHANGE_2: This Helm parameter has been REMOVED
      spec:
        type: LoadBalancer              # CHANGE_3: NEW Helm parameter replacing the old/removed one (above)
        ipFamilyPolicy: PreferDualStack # CHANGE_4: NEW Helm parameter replacing the old/removed one (above)
        externalTrafficPolicy: Local
        allocateLoadBalancerNodePorts: false
    providers:
      kubernetesIngressNGINX:           # CHANGE_5: NEW Helm parameter replacing the old/removed "KubernetesIngressNginx"
        enabled: true
        ingressClass: "rke2-ingress-nginx-migration"
        controllerClass: "rke2.​cattle.​io/ingress-nginx-migration"
EOF
----

上面显示的 `{rke2-traefik Helm chart version}` 是 `{product}` `{static-edge-version}` 版本中用于升级的 RKE2/k3s 版本所提供的（您可以从相应的 https://github.com/rancher/rke2/releases/[RKE2 发布页面] / https://github.com/k3s-io/k3s/releases/[k3s 发布页面] 获取它）。
