关于如何编写更好的技术文档的五条基本规则

== #1 转换视角

____
不要告诉我它是如何工作的...告诉我如何使用它！
____

* 始终设身处地为读者着想
** 我要求读者具备什么样的知识水平？
** 读者想要实现什么目标？
** 读者可能会有什么疑问？
** 可能会出现什么问题？
* 请考虑到您的读者
** 您的时间有限
** 您感到沮丧
** 您承受压力
** 您在嘈杂的环境中工作
** 您是非母语使用者


[IMPORTANT]
====
超过 80% 的读者通过（Google）搜索而来，并且很可能直接进入书中的某个随机章节。
请务必在章节开头提供所有必要的背景信息和要求。
====




== #2 保持简单明了 (KISS)

简短明了的说明更容易理解，也更不容易出错。
这不仅对读者有意义，对本地化工作也同样重要。

语言简洁明了::
+
* 利用 -> *使用*
* 指出 -> *显示*、*告知*、*说明*
* 先决条件 -> *要求*
+
无填充词::
+
* 为了 -> *以*
* 已存在 -> *现有的*
* 全新的 -> *新的*
* 只需执行 -> *执行*
* 请执行 -> *执行*
+
使用现在时态::
+
* 运行 xxx。将出现对话框 yyy。-> *运行 xxx。对话框 yyy 出现。*
+
一个句子只表达一个观点::
+
使用 YaST（提供 X Window UI 和 ncurses 两种界面）来配置和管理系统，并安装新软件或安全更新和补丁。
+
->
+
*使用 YaST 配置和管理系统。*
*也可使用它安装新软件并保持系统更新。*
*YaST 附带一个可在 X Window 下使用的 UI。*
*若要在终端中使用，可以使用 ncurses 界面。*
+
限制替代方案的描述::
+
通常完成某件事的方法不止一种。
将文档限制为 _一种_ 推荐且受支持的方法。
仅在绝对必要时（例如 UI 和命令行）才记录替代方案。

== #3 组织信息

* 将您的文档视为一个漏斗：从一般信息开始，越往后越具体
* 将信息放在重要的地方
** 目标和背景优先
** 要求放在第二位
** 步骤放在最后
** 警告和注意事项需要放在相关位置
** 以上内容也适用于文档的所有章节
* 描述一系列步骤（过程）时，请务必使用有序列表
** 每个过程不超过 10 个步骤（7+/- 2 为理想值）；拆分为不同的任务以缩短长度
** 目标、步骤、结果
* 不要在程序清单中放置任何信息
** ...因为它们不会被翻译
* 不要使用小于 3 级（`==== Level 3 headline`）的标题
* 将超过 80 个字符的命令拆分为多行

== #4 保持一致

重复_并不_是坏事::
+
. 运行命令 XXX -> *运行命令 XXX*
. 执行命令 YYY -> *执行命令 YYY*
. 执行命令 ZZZ -> *执行命令 ZZZ*
+
使用一致的术语::
+
* 软链接、软链接、软链接、软链接 -> *软链接*
* 更新与升级
* 附加产品、附加产品、附加产品 -> *附加产品*

== #5 避免中断

单一的思路::
+
然而，它们并未被标记为已安装。-> *然而，它们并未被标记为已安装。*
+
不要拆分动词::
+
关闭服务器。-> *关闭服务器。*
