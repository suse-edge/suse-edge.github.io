== 硬件

SUSE Telco Cloud 的硬件要求如下：

* **管理群集**：管理群集包含 `SUSE Linux Micro`、`RKE2`、`SUSE Rancher Prime`、`Metal^3^` 等组件，用于管理多个下游集群。根据要管理的下游集群数量，服务器的硬件要求可能会有所不同。
  ** 服务器（`VM` 或 `bare-metal`）的最低要求为：
     *** RAM：最低 8 GB（我们建议至少 16 GB）
     *** CPU：最低 2 个（我们建议至少 4 个处理器）

* **下游集群**：下游集群是为运行电信工作负载而部署的集群。需要特定要求才能启用某些电信功能，例如 `SR-IOV`、`CPU Performance Optimization` 等。
  ** SR-IOV：要以直通模式将 VF（虚拟功能）附加到 CNF/VNF，NIC 必须支持 SR-IOV，并且必须在 BIOS 中启用 VT-d/AMD-Vi。
  ** CPU 处理器：要运行特定的电信工作负载，应调整 CPU 处理器型号，以启用此参考 <<atip-features,表>> 中提供的大多数功能。
  ** 使用虚拟媒体进行安装的固件要求：

== 网络

作为网络架构的参考，下图显示了电信环境的典型网络架构：

image::product-atip-requirements1.png[scaledwidth=100%]

网络架构基于以下组件：

* **管理网络**：此网络用于管理下游集群节点。它用于带外管理。通常，此网络也连接到单独的管理交换机，但也可以使用 VLAN 将其连接到同一服务交换机以隔离流量。
* **控制平面网络**：此网络用于下游集群节点与其上运行的服务之间的通信。此网络还用于节点与外部服务（如 `DHCP` 或 `DNS` 服务器）之间的通信。在某些情况下，对于已连接的环境，交换机/路由器可以通过 Internet 处理流量。
* **其他网络**：在某些情况下，节点可以出于特定目的连接到其他网络。

[NOTE]
====
要使用定向网络配置工作流，管理集群必须具备与下游集群服务器基板管理控制器 (BMC) 的网络连接，以便实现主机准备和配置的自动化。
====

=== 下游节点

在 SUSE Telco Cloud 中，在任何（下游）服务器成为运行中的下游 Kubernetes 集群的一部分（或其自身运行单节点下游 Kubernetes 集群）之前，必须经历一些 https://github.com/metal3-io/baremetal-operator/blob/main/docs/baremetalhost-states.md[裸机主机配置状态]。

== 服务（DHCP、DNS 等）

根据部署环境的类型，可能需要一些外部服务，如 `DHCP`、`DNS` 等：

* **已连接环境**：在这种情况下，节点将连接到互联网（通过路由 L3 协议），外部服务将由客户提供。
* **断开连接 / 隔离环境**：在这种情况下，节点将没有互联网 IP 连接，并且需要额外的服务来在本地镜像定向网络配置工作流所需的内容。
* **文件服务器**：文件服务器用于存储在定向网络配置工作流期间要在下游集群节点上配置的操作系统镜像。`Metal^3^` Helm chart 可以部署一个媒体服务器来存储操作系统镜像——请查看以下 xref:metal3-media-server[章节]，但也可以使用现有的本地 Web 服务器。

== 禁用 systemd 服务

对于电信工作负载，禁用或正确配置在节点上运行的某些服务非常重要，以避免对在节点上运行的工作负载性能（延迟）产生任何影响。

* `rebootmgr` 是一项服务，允许在系统有待处理更新时配置重启策略。
对于电信工作负载，禁用或正确配置 `rebootmgr` 服务非常重要，以避免在系统调度更新时重启节点，从而避免对在节点上运行的服务产生任何影响。

[NOTE]
====
有关 `rebootmgr` 的更多信息，请参阅 https://github.com/SUSE/rebootmgr[rebootmgr GitHub 储存库]。
====

通过运行以下命令验证正在使用的策略：

[,shell]
----
cat /etc/rebootmgr.conf
[rebootmgr]
window-start=03:30
window-duration=1h30m
strategy=best-effort
lock-group=default
----

您可以通过运行以下命令来禁用它：

[,shell]
----
sed -i 's/strategy=best-effort/strategy=off/g' /etc/rebootmgr.conf
----

或者使用 `rebootmgrctl` 命令：

[,shell]
----
rebootmgrctl strategy off
----

[NOTE]
====
此设置 `rebootmgr` 策略的配置可以使用定向网络配置工作流自动完成。有关更多信息，请查看 <<atip-automated-provisioning,自动化配置文档>>。
====

* `transactional-update` 是一项允许由系统控制自动更新的服务。对于电信工作负载，禁用自动更新以避免对节点上运行的服务产生任何影响非常重要。

要禁用自动更新，您可以运行：

[,shell]
----
systemctl --now disable transactional-update.timer
systemctl --now disable transactional-update-cleanup.timer
----

* `fstrim` 是一项允许每周自动修剪文件系统的服务。对于电信工作负载，禁用自动修剪以避免对节点上运行的服务产生任何影响非常重要。

要禁用自动修剪，您可以运行：

[,shell]
----
systemctl --now disable fstrim.timer
----
