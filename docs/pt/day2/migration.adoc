Esta seção explica como migrar seus clusters `management` e `downstream` de `Edge {previous-edge-version}` para `Edge {static-edge-version}`.

[IMPORTANT]
====
Sempre realize migrações de cluster a partir da `latest Z-stream` release do `Edge {previous-edge-version}`.

Sempre migre para a `Edge {static-edge-version}` release. Para upgrades pós-migração subsequentes, consulte as seções de cluster <<day2-mgmt-cluster, de gerenciamento>> e <<day2-downstream-clusters, downstream>>.
====

[#day2-migration-mgmt-prereq]
=== Pré-requisitos

==== Atualize os CRDs do Bare Metal Operator

[NOTE]
====
Aplica-se apenas a clusters que exigem <<components-metal3>> fazer upgrade do chart.
====

O gráfico Helm `Metal^3^` inclui os CRDs link:https://book.metal3.io/bmo/introduction.html[Bare Metal Operator (BMO)] aproveitando o diretório link:https://helm.sh/docs/chart_best_practices/custom_resource_definitions/#method-1-let-helm-do-it-for-you[CRD] do Helm.

No entanto, essa abordagem tem certas limitações, particularmente a incapacidade de atualizar CRDs neste diretório usando o Helm. Para obter mais informações, consulte a link:https://helm.sh/docs/chart_best_practices/custom_resource_definitions/#some-caveats-and-explanations[documentação do Helm].

Como resultado, antes de fazer upgrade do Metal^3^ para uma versão compatível com `Edge {static-edge-version}`, os usuários devem fazer upgrade manualmente dos CRDs do BMO subjacentes.

Em uma máquina com `Helm` instalado e `kubectl` configurado para apontar para o seu cluster `{cluster-type}`:

. Aplique manualmente os CRDs do BMO:
+
[,bash,subs="attributes"]
----
helm show crds oci://registry.suse.com/edge/charts/metal3 --version {version-metal3-chart} | kubectl apply -f -
----

[#day2-migration-mgmt-upgrade-controller]
=== Upgrade Controller

[IMPORTANT]
====
O `Upgrade Controller` atualmente suporta migrações de release Edge apenas para *clusters de gerenciamento que não são air-gapped*.
====

Os tópicos a seguir são abordados como parte desta seção:

<<day2-migration-mgmt-upgrade-controller-prereq>> - pré-requisitos específicos para o `Upgrade Controller`.

<<day2-migration-mgmt-upgrade-controller-migration>> - etapas para migrar um cluster `{cluster-type}` para uma nova release Edge usando o `Upgrade Controller`.

[#day2-migration-mgmt-upgrade-controller-prereq]
==== Pré-requisitos

===== Edge {version-edge} Upgrade Controller

Antes de usar o `Upgrade Controller`, você deve primeiro garantir que ele esteja executando uma versão capaz de migrar para o release Edge desejado.

Para fazer isso:

. Se você já tiver o `Upgrade Controller` implantado a partir de um release Edge anterior, faça upgrade do seu chart:
+
[,bash,subs="attributes"]
----
helm upgrade upgrade-controller -n upgrade-controller-system oci://registry.suse.com/edge/charts/upgrade-controller --version {version-upgrade-controller-chart}
----

. Se você *não* tiver `Upgrade Controller` implantado, siga <<components-upgrade-controller-installation>>.

[#day2-migration-mgmt-upgrade-controller-migration]
==== Etapas de migração

Realizar uma migração de cluster `{cluster-type}` com o `Upgrade Controller` é fundamentalmente semelhante à execução de um upgrade.

A única diferença é que seu `UpgradePlan` *deve* especificar a versão de lançamento `{static-edge-version}`:

[,yaml,subs="attributes"]
----
apiVersion: lifecycle.suse.com/v1alpha1
kind: UpgradePlan
metadata:
  name: upgrade-plan-mgmt
  # Change to the namespace of your Upgrade Controller
  namespace: CHANGE_ME
spec:
  releaseVersion: {static-edge-version}
----

Para obter informações sobre como usar o `UpgradePlan` acima para realizar uma migração, consulte <<{cluster-type}-day2-upgrade-controller,processo de upgrade do Upgrade Controller>>.

[#day2-migration-mgmt-fleet]
=== Fleet

[NOTE]
====
Sempre que possível, use o <<day2-migration-mgmt-upgrade-controller>> para migração.

Consulte esta seção apenas para casos de uso não cobertos pelo `Upgrade Controller`.
====

Realizar uma migração de cluster `{cluster-type}` com `Fleet` é fundamentalmente semelhante à execução de um upgrade.

As *principais* diferenças são:

. As Fleet *devem ser usadas* a partir da versão link:https://github.com/suse-edge/fleet-examples/releases/tag/{static-fleet-examples-tag}[{static-fleet-examples-tag}] do repositório `suse-edge/fleet-examples`.

. Os charts agendados para um upgrade *devem* ser atualizados para releases compatíveis com o `Edge {static-edge-version}`. Para obter uma lista dos componentes `Edge {static-edge-version}`, consulte <<release-notes-3-4-0>>.

[IMPORTANT]
====
Para garantir uma migração `Edge {static-edge-version}` bem-sucedida, é importante que os usuários cumpram os pontos descritos acima.
====

Considerando os pontos acima, os usuários podem seguir a documentação do <<{cluster-type}-day2-fleet, Fleet>> do cluster `{cluster-type}` para obter um guia abrangente sobre as etapas necessárias para realizar uma migração.
