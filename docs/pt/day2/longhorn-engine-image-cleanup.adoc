Esta seção descreve como implementar a limpeza automatizada de imagens obsoletas do Longhorn Engine que se acumulam após fazer upgrade do cluster.

=== Declaração do problema

O Longhorn não remove automaticamente imagens antigas do Longhorn Engine após fazer upgrade. Esta é uma decisão de design intencional para evitar perda acidental de dados — o Longhorn retém versões anteriores da imagem do Longhorn Engine como uma medida de segurança caso seja necessário um rollback.

No entanto, em ambientes de produção com upgrades frequentes, essas imagens do Longhorn Engine não utilizadas se acumulam com o tempo, resultando em:

* **Consumo de armazenamento**: Cada imagem do Longhorn Engine consome espaço em disco nos nós do cluster
* **Sobrecarga de recursos**: O Kubernetes gerencia recursos de imagem adicionais desnecessariamente
* **Complexidade operacional**: Identificação e limpeza manual de imagens obsoletas


=== Quando implementar a limpeza

A limpeza de imagens do Longhorn Engine é recomendada nos seguintes cenários:

* **Atualizações regulares de cluster**: Ambientes que realizam upgrades frequentes de versão do Longhorn
* **Implantações com restrição de armazenamento**: Clusters com capacidade de armazenamento de nó limitada
* **Higiene operacional**: Como parte dos procedimentos de manutenção de rotina do Dia 2

[NOTE]
====
Este procedimento de limpeza é classificado como **baixo risco** porque remove apenas imagens do Longhorn Engine com zero referências ativas (`refCount == 0`). Imagens atualmente em uso por volumes são protegidas e não serão excluídas.
====

=== Arquitetura da solução

A solução de limpeza usa um CronJob do Kubernetes que executa tarefas periódicas de manutenção:

. **Descoberta**: Identifica a versão mais recente da imagem do Longhorn Engine implantada no cluster
. **Seleção de candidatos**: Localiza todas as versões de imagem do Longhorn Engine mais antigas sem referências de volume ativas
. **Execução da limpeza**: Exclui imagens do Longhorn Engine obsoletas que atendem aos critérios de segurança
. **Registro de auditoria**: Registra operações de limpeza para visibilidade operacional

A implementação requer:

* **ServiceAccount**: Para autenticação na API do Kubernetes
* **Permissões RBAC**: Acesso de leitura e exclusão aos recursos `engineimages.longhorn.io`
* **CronJob**: Contêiner de execução agendada com lógica de limpeza

=== Implementação

A solução completa de limpeza consiste em quatro manifestos do Kubernetes implantados no namespace `longhorn-system`.

. **Create ServiceAccount**
+
Crie uma ServiceAccount dedicada para o CronJob de limpeza:
+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata:
  name: longhorn-engineimage-cleanup
  namespace: longhorn-system
  labels:
    app: longhorn-engineimage-cleanup
----

. **Configurar permissões de RBAC**
+
.. Defina uma Role com as permissões mínimas necessárias:
+
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: longhorn-engineimage-cleanup
  namespace: longhorn-system
  labels:
    app: longhorn-engineimage-cleanup
rules:
- apiGroups: [longhorn.io]
  resources: [engineimages]
  verbs: [get, list, delete]
----
+
.. Vincule a Role à ServiceAccount:
+
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: longhorn-engineimage-cleanup
  namespace: longhorn-system
  labels:
    app: longhorn-engineimage-cleanup
subjects:
- kind: ServiceAccount
  name: longhorn-engineimage-cleanup
  namespace: longhorn-system
roleRef:
  kind: Role
  name: longhorn-engineimage-cleanup
  apiGroup: rbac.authorization.k8s.io
----

. **Implantar CronJob de limpeza**
+
Implante o CronJob de limpeza automatizada:
+
[source,yaml]
----
apiVersion: batch/v1
kind: CronJob
metadata:
  name: longhorn-engineimage-cleanup
  namespace: longhorn-system
  labels:
    app: longhorn-engineimage-cleanup
  annotations:
    description: "Cleanup old Longhorn engine images left over after upgrades"
    source: "SUSE Edge Telco Cloud - Day 2 Operations"
spec:
  # Execute weekly on Sunday at 2:00 AM UTC
  schedule: "0 2 * * 0"
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 3
  concurrencyPolicy: Forbid
  jobTemplate:
    spec:
      backoffLimit: 2
      activeDeadlineSeconds: 600
      template:
        metadata:
          labels:
            app: longhorn-engineimage-cleanup
        spec:
          serviceAccountName: longhorn-engineimage-cleanup
          restartPolicy: Never
          automountServiceAccountToken: true
          containers:
          - name: cleanup
            image: registry.suse.com/bci/bci-base:15.6
            command:
            - sh
            - -c
            - |
              set -e

              # Install required tools
              zypper --non-interactive install curl jq

              # Install kubectl from official Kubernetes
              curl -LO "https://dl.k8s.io/release/v1.36.3/bin/linux/amd64/kubectl"
              chmod +x kubectl
              mv kubectl /usr/local/bin/

              echo "=== Longhorn Engine Image Cleanup ==="
              echo "Automated maintenance - Day 2 Operations"
              echo ""

              echo "Step 1: Discovering latest engine image version..."

              ENGINE_IMAGES=$(kubectl get engineimages.longhorn.io -n longhorn-system -o json)

              LATEST_VERSION=$(echo "$ENGINE_IMAGES" | jq -r '
                .items[]
                | select(.status.version != null)
                | .status.version' |
                sed 's/^v//' |
                sort -V |
                tail -1)

              if [ -z "$LATEST_VERSION" ]; then
                echo "No engine images found. Nothing to cleanup."
                exit 0
              fi

              echo "Latest version detected: v${LATEST_VERSION}"
              echo ""

              echo "Step 2: Identifying obsolete engine images..."

              TO_DELETE=$(echo "$ENGINE_IMAGES" | jq -r --arg latest "v${LATEST_VERSION}" '
                .items[]
                | select(.status.version != $latest)
                | select(.status.refCount == 0)
                | .metadata.name')

              if [ -z "$TO_DELETE" ]; then
                echo "No obsolete engine images found"
                echo "All engine images are either:"
                echo "  - Latest version (v${LATEST_VERSION})"
                echo "  - Still in use (refCount > 0)"
                exit 0
              fi

              DELETE_COUNT=$(echo "$TO_DELETE" | wc -l | tr -d ' ')
              echo "Found $DELETE_COUNT obsolete engine image(s) for deletion:"
              echo "$TO_DELETE"
              echo ""

              COUNT=0
              FAILED=0
              for IMAGE_NAME in $TO_DELETE; do
                VERSION=$(echo "$ENGINE_IMAGES" | jq -r --arg name "$IMAGE_NAME" \
                  '.items[] | select(.metadata.name == $name) | .status.version')
                REFCOUNT=$(echo "$ENGINE_IMAGES" | jq -r --arg name "$IMAGE_NAME" \
                  '.items[] | select(.metadata.name == $name) | .status.refCount')

                echo "Deleting: $IMAGE_NAME (version: $VERSION, refCount: $REFCOUNT)"

                if kubectl delete engineimages.longhorn.io "$IMAGE_NAME" -n longhorn-system; then
                  COUNT=$((COUNT + 1))
                  echo "  ✓ Deleted successfully"
                else
                  FAILED=$((FAILED + 1))
                  echo "  ✗ Failed to delete"
                fi
              done

              echo ""
              echo "=== Cleanup Summary ==="
              echo "Latest version: v${LATEST_VERSION}"
              echo "Successfully deleted: $COUNT obsolete engine images"
              echo "Failed deletions: $FAILED engine images"

              if [ $FAILED -gt 0 ]; then
                exit 1
              fi

              echo ""
              echo "Cleanup completed successfully"
----

. **Aplique a configuração**
+
.. Salve todos os quatro manifestos em um único arquivo (por exemplo, `longhorn-engine-cleanup.yaml`), então implante-os no cluster:
+
[source,bash]
----
kubectl apply -f longhorn-engine-cleanup.yaml
----
+
.. Verifique se o CronJob foi criado:
+
[source,bash]
----
kubectl get cronjob -n longhorn-system longhorn-engineimage-cleanup
----
+
Saída esperada:
+
[source,text]
----
NAME                            SCHEDULE     SUSPEND   ACTIVE   LAST SCHEDULE   AGE
longhorn-engineimage-cleanup    0 2 * * 0    False     0        <none>          5s
----

=== Procedimentos operacionais

Esta seção descreve as tarefas operacionais diárias para gerenciar o CronJob de limpeza de imagem do Longhorn Engine, incluindo execução manual, personalização de agendamento, monitoramento e verificação.

==== Execução manual

Para executar a limpeza imediatamente sem esperar pelo horário agendado, execute o seguinte comando:

[source,bash]
----
kubectl create job --from=cronjob/longhorn-engineimage-cleanup \
  longhorn-engineimage-cleanup-manual-$(date +%Y%m%d-%H%M%S) \
  -n longhorn-system
----

Monitore a execução manual:

. Observe o status do job:
+
[source,bash]
----
kubectl get jobs -n longhorn-system -w
----

. Visualize os logs do job:
+
[source,bash]
----
kubectl logs -n longhorn-system -l app=longhorn-engineimage-cleanup --tail=100
----

==== Configuração de agendamento

A programação padrão executa a limpeza semanalmente aos domingos às 2:00 AM UTC:

[source,yaml]
----
schedule: "0 2 * * 0"
----

Alternativas de programação comuns:

* **Diariamente às 3:00 AM**: `"0 3 * * *"`
* **Mensalmente no dia 1º às 4:00 AM**: `"0 4 1 * *"`
* **A cada 6 horas**: `"0 */6 * * *"`

Modifique a programação:

[source,bash]
----
kubectl patch cronjob longhorn-engineimage-cleanup \
  -n longhorn-system \
  --type='merge' \
  -p '{"spec":{"schedule":"0 3 * * *"}}'
----

==== Monitoramento e logs

Visualizar histórico de limpeza:

* Listar tarefas concluídas:
+
[source,bash]
----
kubectl get jobs -n longhorn-system -l app=longhorn-engineimage-cleanup
----

* Visualizar logs da última execução bem-sucedida:
+
[source,bash]
----
kubectl logs -n longhorn-system \
  -l app=longhorn-engineimage-cleanup \
  --tail=200 \
  | grep -A 50 "Cleanup Summary"
----

Inspecionar execução de tarefa específica:

[source,bash]
----
# Get job name
JOB_NAME=$(kubectl get jobs -n longhorn-system \
  -l app=longhorn-engineimage-cleanup \
  --sort-by=.metadata.creationTimestamp \
  -o jsonpath='{.items[-1].metadata.name}')

# View job details
kubectl describe job $JOB_NAME -n longhorn-system

# View job logs
kubectl logs job/$JOB_NAME -n longhorn-system
----

==== Verificação

Após a execução da limpeza, verifique se apenas as imagens atuais do Longhorn Engine permanecem:

. Listar todas as imagens do Longhorn Engine:
+
[source,bash]
----
kubectl get engineimages.longhorn.io -n longhorn-system
----

. Verificar contagens de referência:
+
[source,bash]
----
kubectl get engineimages.longhorn.io -n longhorn-system \
  -o custom-columns=NAME:.metadata.name,VERSION:.status.version,REFCOUNT:.status.refCount
----

Saída esperada mostrando apenas a versão mais recente com referências ativas:

[source,text]
----
NAME                                VERSION     REFCOUNT
ei-acba2c08                         v1.12.1     3
----
